## Dogfood evidence (post-1.0)

Since tagging 1.0.0, the skill has been E2E-audited against **6 real projects**:

| Project | Stack | DESIGN.md | UX-CONTRACT | Key finding |
|---------|-------|-----------|-------------|-------------|
| namitalk-ai-powered | Next.js + Electron | ✅ seeded | ✅ seeded | Desktop+web dual-surface |
| scopelytics-ai-powered | Next.js | ❌ lint đỏ | ❌ | `confirm()` thật, forms thiếu `noValidate` |
| ai-harness-agents-mornitoring | **Svelte 5** + Tauri | ❌ | ❌ | Svelte false positive trong grep |
| webinar-stock_CMS | Next.js JP | ❌ | ❌ | Password reveal, clickable div |
| webinar-stock_FE | Next.js JP | ❌ lint đỏ | ❌ | `window.alert`, infinite scroll |
| transport-system | **Vite + React Router 6** | ❌ | ❌ | Clean native dialogs, sortable `aria-sort` |

### Key post-1.0 gaps

1. **Non-Next dry-run** — Svelte + Vite SPA evidence collected. Readiness still deferred but the gap is understood.
2. **IME-safe search (`isComposing`)** — 0/6 projects implement it correctly. Needs stronger contract in skill.
3. **Custom scrollbar + `scrollbar-gutter`** — 5/6 projects missing. Should be part of baseline design contract.
4. **Sortable header `aria-sort`** — transport-system exposed missing `<button>` + `aria-sort` on table headers.
5. **ConfirmIntent axis** — Several projects use same destructive variant for soft-delete and hard-delete.
6. **Search clear X** — Several projects rely on browser native `type="search"` X instead of app-owned button.

## Verdict

**Ready for 1.0.0 — core contract is stable, discoverable, and verified on 3 real projects.**

All 15 case study requirements are covered. Former optional fixtures/prose items are filled except the non-Next dry-run and IME/search/scrollbar baselines. Tag/use 1.0.0; treat Vue/Svelte/Vite dry-run and IME/scrollbar/aria-sort as post-1.0 PATCH/MINOR.
